# فحص توافق قواعد Firebase المقترحة — 18 أكتوبر 2026

## النتيجة
نجح فحص محلي ساكن للشيفرة واختبار محاكاة قرارات الصلاحيات (**ليس اختبار Firebase Emulator أو الخادم المباشر**).

- أسماء الخدمات الثماني في الناشر وصفحة الزائر متوافقة مع الصيغة:
  `^hazm_(clock|compass|pd|family|plan|activities|safety|quality)_(manifest|part_[0-9]{3})$`.
- الزائر يستعمل `getDoc` للمستندات المسماة ولا يعتمد على `getDocs` أو استعراض مجموعات.
- 15 حالة محاكاة محلية مرّت: إتاحة الزائر عند التفعيل، رفض الزائر عند التعطيل، قراءة الإدارة، رفض وصول الزائر إلى supervisory_visits/private_data، منع تعديل admins، رفض مستند monitor ضمن public_content.

## لم يُختبر بعد
- صياغة وتقييم القواعد بواسطة Firebase Rules Emulator الحقيقي.
- القراءة والكتابة الفعلية بحساب إداري وحساب زائر مع Rules المنشورة.
- مدى خصوصية **المحتوى داخل** كل مستند عام، وليس اسم المستند فقط.
- ترحيل سجلات الزيارات الإشرافية واختبار الاستعادة.

## الإجراء التالي
تشغيل الاختبارات في Firebase Rules Playground/Emulator قبل النشر، ثم تعديل القواعد بعد نسخة احتياطية واتفاق واضح. **لا تنشر القواعد المقترحة اعتمادًا على الفحص الساكن وحده.**

## سلامة البيانات
لا تعديل على main أو إعدادات Firebase أو السجلات المحلية.
